EVOLUTION GO - WEBHOOKS DOCS

Configuration
Webhooks
Webhooks allow Evolution Go to send real-time notifications to your application when events occur on WhatsApp, such as receiving messages, connection updates, calls, and more.
​
Quick Start
Follow these steps to configure and receive webhooks from Evolution Go.
​
Prerequisites
Before configuring webhooks, you need:
Evolution Go installed and running — see the installation guide
An instance created — see Getting Started
Your API Key (GLOBAL_API_KEY configured in .env)
An accessible URL to receive events
For quick testing, use webhook.site to generate a temporary URL and view received events in real-time. For local development, use ngrok to expose your local server to the internet.
​
Step 1: Connect the instance with webhook
Configure the webhook when connecting your instance by sending a request to the connection endpoint.
​
Method
POST {BASE_URL}/instance/connect
​
Header
Key	Value	Description
Content-Type	application/json	Content type
apikey	YOUR_GLOBAL_API_KEY	Global API key configured in .env
instanceId	249aad2e-68f9-464f-bc84-aca560c38f0e	UUID of the instance you want to connect
The API Key is the value of the GLOBAL_API_KEY variable configured in the Evolution Go .env file. Never expose this key publicly. See more details in Getting Started.
​
Body
{
  "webhookUrl": "https://webhook.site/your-unique-id",
  "subscribe": ["ALL"],
  "immediate": true
}
​
cURL Example
curl -X POST 'http://localhost:8080/instance/connect' \
  -H 'Content-Type: application/json' \
  -H 'apikey: YOUR_GLOBAL_API_KEY' \
  -H 'instanceId: 249aad2e-68f9-464f-bc84-aca560c38f0e' \
  -d '{
    "webhookUrl": "https://webhook.site/your-unique-id",
    "subscribe": ["ALL"],
    "immediate": true
  }'
​
JavaScript Example
const response = await fetch('http://localhost:8080/instance/connect', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'apikey': 'YOUR_GLOBAL_API_KEY',
    'instanceId': '249aad2e-68f9-464f-bc84-aca560c38f0e'
  },
  body: JSON.stringify({
    webhookUrl: 'https://webhook.site/your-unique-id',
    subscribe: ['ALL'],
    immediate: true
  })
});

const data = await response.json();
console.log(data);
​
Python Example
import requests

response = requests.post(
    'http://localhost:8080/instance/connect',
    headers={
        'Content-Type': 'application/json',
        'apikey': 'YOUR_GLOBAL_API_KEY',
        'instanceId': '249aad2e-68f9-464f-bc84-aca560c38f0e'
    },
    json={
        'webhookUrl': 'https://webhook.site/your-unique-id',
        'subscribe': ['ALL'],
        'immediate': True
    }
)

print(response.json())
​
Step 2: Pair with WhatsApp
After connecting, you will receive a QRCode event on your webhook with the QR Code image in base64:
Open WhatsApp on your phone
Go to Settings > Linked Devices > Link a Device
Scan the QR Code received on your webhook (decode the qrcode base64 field to display the image)
If you prefer to use Pairing Code instead of QR Code, send the phone field in the body:
{
  "webhookUrl": "https://webhook.site/your-unique-id",
  "subscribe": ["ALL"],
  "phone": "5511999999999"
}
​
Step 3: Confirm the connection
After successful pairing, you will receive a sequence of events: PairSuccess → Connected → OfflineSyncCompleted. If you received these 3 events, your webhook is correctly configured.
​
Step 4: Receive messages
From now on, every message received on WhatsApp will be sent as a Message event to your URL.
User sends message → WhatsApp → Evolution Go → HTTP POST → Your Webhook
​
Processing on your server

Node.js (Express)

Python (Flask)
const express = require('express');
const app = express();
app.use(express.json());

app.post('/webhook', (req, res) => {
  const { event, data, instanceId } = req.body;

  switch (event) {
    case 'Message':
      const sender = data.Info.PushName || data.Info.Sender;
      const text = data.Message.conversation;
      console.log(`[${instanceId}] ${sender}: ${text}`);
      break;
    case 'Connected':
      console.log(`Instance ${instanceId} connected!`);
      break;
    case 'QRCode':
      console.log(`QR Code received for ${instanceId}`);
      break;
    default:
      console.log(`Event: ${event}`);
  }

  res.status(200).json({ received: true });
});

app.listen(3000, () => console.log('Webhook running on port 3000'));
Your endpoint must respond with an HTTP 2xx status (200-299) within 30 seconds. Otherwise, Evolution Go will retry up to 5 times with a 30-second interval between each attempt.
​
Detailed Configuration
Webhook configuration is done when connecting an instance, through the POST /instance/connect endpoint.
​
Instance Webhook
When connecting an instance, you can set the webhook URL and the events you want to receive:
POST /instance/connect
{
  "webhookUrl": "https://your-domain.com/webhook",
  "subscribe": [
    "MESSAGE",
    "SEND_MESSAGE",
    "CONNECTION",
    "QRCODE"
  ],
  "immediate": true,
  "phone": "5511999999999"
}
​
Parameters
Parameter	Type	Required	Description
webhookUrl	string	No	URL that will receive events via HTTP POST
subscribe	string[]	No	List of event types to receive. If empty, only receives MESSAGE
immediate	boolean	No	Connect immediately without waiting for QR Code
phone	string	No	Phone number for pairing
rabbitmqEnable	string	No	"enabled" to activate RabbitMQ delivery
websocketEnable	string	No	"enabled" to activate WebSocket delivery
natsEnable	string	No	"enabled" to activate NATS delivery
​
Global Webhook
You can set a global webhook via environment variable. It will receive events from all instances, in addition to each instance’s individual webhooks.
.env
# Global webhook URL (receives events from all instances)
WEBHOOK_URL=https://your-domain.com/webhook/global

# Include media files in webhook payload (default: true)
WEBHOOK_FILES=true
When configured, both webhooks are triggered: the global one (defined by WEBHOOK_URL) and the instance one (defined in webhookUrl). This allows having a centralized monitoring system alongside instance-specific integrations.
​
Event Types
When configuring the webhook, you can subscribe to the following event types:
Event Type	Description	Included Events
ALL	Receives all available events	All below
MESSAGE	Received messages	Message
SEND_MESSAGE	Sent messages	SendMessage
READ_RECEIPT	Read confirmations	Receipt (Read, ReadSelf, Delivered)
PRESENCE	Online/offline presence status	Presence
HISTORY_SYNC	History synchronization	HistorySync
CHAT_PRESENCE	Chat presence (typing, recording)	ChatPresence, Archive
CALL	Call events	CallOffer, CallRelayLatency, CallTerminate
CONNECTION	Connection status	Connected, PairSuccess, LoggedOut, OfflineSyncCompleted
LABEL	Label management	LabelEdit, LabelAssociationChat, LabelAssociationMessage
CONTACT	Contact updates	Contact, PushName
GROUP	Group events	GroupInfo, JoinedGroup
NEWSLETTER	Channel/newsletter events	NewsletterJoin, NewsletterLeave
QRCODE	QR Code events	QRCode, QRTimeout, QRSuccess
Use "ALL" in the subscribe list to receive all events without needing to list each one individually.
​
Payload Structure
All webhooks are sent as HTTP POST requests with Content-Type: application/json. The base payload structure is:
{
  "event": "EventName",
  "data": { ... },
  "instanceId": "instance-uuid",
  "instanceToken": "instance_token"
}
Field	Type	Description
event	string	Name of the event that occurred
data	object	Event-specific data (varies by event)
instanceId	string	Instance UUID
instanceToken	string	Instance authentication token

Message
Emitted when a message is received. The payload varies depending on the message type. All message events share the same base structure in data, with the Info object containing metadata and Message containing the content.
​
Common Info object fields
Field	Type	Description
Info.Chat	string	Chat JID (individual or group)
Info.Sender	string	Sender JID
Info.SenderAlt	string	Alternative sender JID (LID)
Info.IsFromMe	boolean	true if the message was sent by the instance itself
Info.IsGroup	boolean	true if the message is from a group
Info.ID	string	Unique message ID
Info.Type	string	Message type (text, media, etc.)
Info.PushName	string	Sender display name
Info.Timestamp	string	Message date/time (ISO 8601)
Info.MediaType	string	Media type (image, video, audio, document)
Info.VerifiedName	object	Verified name information (Business accounts)
​
Additional common fields
Field	Type	Description
IsEphemeral	boolean	Ephemeral/disappearing message
IsViewOnce	boolean	View once message
IsViewOnceV2	boolean	View once v2 message
IsViewOnceV2Extension	boolean	View once v2 extension
IsDocumentWithCaption	boolean	Document with caption
IsLottieSticker	boolean	Animated Lottie sticker
IsEdit	boolean	Edited message

Retry Policy
Evolution Go has an automatic retry system to ensure webhook delivery:
Setting	Value
Maximum retries	5
Interval between retries	30 seconds
HTTP Method	POST
Content-Type	application/json
Expected response	HTTP status 2xx
If all 5 attempts fail, the event is discarded and an error log is recorded.
Make sure your webhook endpoint responds with an HTTP 2xx status (200-299) to confirm receipt. Any response outside this range will be treated as a failure and will trigger a retry.
​
Alternative Delivery Channels
In addition to HTTP webhooks, Evolution Go supports other event delivery channels:
RabbitMQ / AMQP
Send via AMQP queues. Configure with rabbitmqEnable: "enabled" on instance connection and the AMQP_URL, AMQP_GLOBAL_ENABLED, and AMQP_GLOBAL_EVENTS variables.
NATS
Send via NATS messaging. Configure with natsEnable: "enabled" on connection and the NATS_URL, NATS_GLOBAL_ENABLED, and NATS_GLOBAL_EVENTS variables.
WebSocket
Receive events in real-time via WebSocket. Configure with websocketEnable: "enabled" on instance connection.
Multiple channels can be activated simultaneously. For example, you can receive events via HTTP webhook and RabbitMQ at the same time.
